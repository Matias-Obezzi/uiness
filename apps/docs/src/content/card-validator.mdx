An optional companion to the [Credit Card](/docs/components/credit-card) component. The card works on its own from what is typed; this package tells it more: the bank or fintech that issued the card, whether it is debit or credit, prepaid, and its country, from the first 6 digits. It also repeats the form's checks where they can be trusted, on your server.

## What it uses

The first 6 to 8 digits of a card number, its BIN (or IIN), are assigned to the issuer. The network follows public rules (the component already finds it from the first digits), but which bank or fintech issued a BIN does not, so it takes a lookup.

By default that is [binlist.net](https://binlist.net): free, no key. Two things to know:

- **It refuses browsers.** Any request carrying an `Origin` header gets a 403, so it has to be called from a server, and the package gives you that server endpoint.
- **It allows a few lookups an hour per address**, so answers are cached: in memory, and by your CDN for a week. A BIN is shared by thousands of cards, so most lookups never leave the cache.

Its data is community kept and can be out of date, newer fintechs most of all. Treat the issuer as a nicety on the card, not a fact to decide on. For an answer you can rely on, ask your payment provider (Mercado Pago's `getIssuers`, for one) through the `lookup` option.

Only the BIN ever leaves the browser. PCI DSS lets the first 6 and last 4 digits be shown and stored; the endpoint refuses anything but 6 to 8 digits, so a full number cannot reach it.

## How to implement it

**1. An endpoint on your server**, at `/api/card` by default. `createCardHandler` takes a web `Request` and returns a `Response`:

```ts
// app/api/card/route.ts (Next.js), or api/card.ts on Vercel
import { createCardHandler } from '@uiness/card-validator'

export const GET = createCardHandler()
```

```ts
// Hono, Bun, Deno, Remix: anything with web requests
const card = createCardHandler()
app.get('/api/card', (c) => card(c.req.raw))
```

It answers `GET /api/card?bin=424242` with the details, `404` for a BIN no one knows, `400` for anything but 6 to 8 digits, and `502` when the lookup failed (not cached, so the next request retries).

**2. The hook beside the form.** It asks once the number has 6 digits, once per BIN for the whole page:

```tsx
import { useCardInfo } from '@uiness/card-validator/react'
import { CreditCardForm } from '@/components/ui/credit-card'

export function Checkout() {
  const [number, setNumber] = useState('')
  const info = useCardInfo(number)
  return <CreditCardForm issuer={info?.bank} onChange={(card) => setNumber(card.number)} />
}
```

`info` is `null` until there is an answer, and when there is none: the card is drawn without the issuer and nothing else changes. Pass `{ endpoint }` for another path.

**3. Check again on the server**, if your server receives the card. The form's checks run in the browser, where anyone can skip them. (Receiving card numbers puts your server in PCI DSS scope; with your payment provider's hosted fields, the provider checks them and this step is theirs.)

```ts
import { validateCard } from '@uiness/card-validator'

const { valid, brand, errors } = validateCard({ number, expiry, cvc })
// errors: { number?: 'invalid', expiry?: 'invalid' | 'expired', cvc?: 'invalid' }
```

The same rules as the form: the brand's lengths and Luhn digit, a real month not yet passed, a code as long as the brand's. Local networks without a rule here (Cabal, Naranja, Elo) pass on their Luhn digit and any card length.

## Another source

`lookup` takes any `(bin) => Promise<CardInfo | null>`: your payment provider, a paid BIN database, or a table of your own.

```ts
import { type BinLookup, createCardHandler } from '@uiness/card-validator'

const lookup: BinLookup = async (bin) => {
  const res = await fetch(`https://bins.example.com/${bin}`, { headers: { Authorization: KEY } })
  if (res.status === 404) return null
  if (!res.ok) throw new Error(`bins answered ${res.status}`)
  const data = await res.json()
  return { bin, bank: data.issuer, type: data.funding, countryCode: data.country }
}

export const GET = createCardHandler({ lookup, maxAge: 86400 })
```

Return `null` for a BIN that is not known, and throw when the lookup failed so it is retried instead of cached.

## API

| Export | Description |
| --- | --- |
| `createCardHandler({ lookup?, maxAge? })` | The `GET ?bin=` endpoint. `maxAge` is how long a CDN keeps an answer, a week by default. |
| `lookupBin(bin)` | binlist.net, server side. |
| `useCardInfo(number, { endpoint? })` | From `/react`: the `CardInfo` of the card being typed, or `null`. |
| `validateCard({ number, expiry?, cvc? }, now?)` | `{ brand, valid, errors }`, for the fields given. |
| `cardBrand`, `luhn`, `expiryState`, `binOf` | The checks one by one. `binOf` gives the first 6 digits, or `null`. |

`CardInfo` is `{ bin, scheme?, type?, prepaid?, product?, bank?, country?, countryCode? }`, with whatever the lookup knows.
