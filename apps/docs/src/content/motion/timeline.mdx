Entries down a vertical line that lights up as you scroll. Each entry's dot turns on when it passes the reading position, and its heading sticks while its content scrolls by.

## Usage

```tsx
import { Timeline, TimelineItem } from '@/components/ui/timeline'

<Timeline>
  <TimelineItem date="March 2026" title="Launch">
    <p>What happened.</p>
  </TimelineItem>
</Timeline>
```

## Props

| Prop | Default | Description |
| --- | --- | --- |
| `color` | primary | Color of the lit part of the line. |
| `anchor` | `0.6` | Where on the screen the line catches up with you, 0 to 1. |
| `driver` | `'auto'` | `auto`, `css` or `js`. See below. |

`TimelineItem` takes `date`, `title` and `icon`, which replaces the dot.

## CSS scroll-driven mode

By default (`driver="auto"`) the line and the dots run on CSS scroll-driven animations. The timeline declares a view timeline whose viewport is cut down to a line at `anchor`, and the lit part of the line grows along it with `animation-timeline`. Each entry has a view timeline of its own, and its dot lights up over the first `2rem` of scrolling past the anchor. Nothing runs in JavaScript while you scroll, and it works with JavaScript turned off.

`auto` switches to `@uiness/scroll` after mount when the browser has no scroll-driven animations, or when an ancestor with `overflow: hidden` (or `auto` without anything to scroll) sits between the timeline and the real scroller, since a CSS view timeline follows the nearest scroll container even when it never scrolls. `driver="css"` never measures anything, and `driver="js"` always does.

With the CSS driver the dots are lit by the stylesheet, so `data-state` on the entries stays `active`; style on it only with `driver="js"`. The server HTML shows the line fully lit and every dot active, which is also what browsers without scroll-driven animations show when JavaScript does not run.

Browser support for CSS scroll-driven animations: Chrome and Edge 115 and later, Opera 101 and later, Safari 26 and later. Firefox has them only behind a flag at the time of writing, so it gets the JavaScript driver (or, with `driver="css"`, the static final state).
