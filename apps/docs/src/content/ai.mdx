Coding agents can read uiness as well as people do. Connect yours to the MCP server and it searches the registry, reads these docs and fetches the source of any item, instead of guessing props from memory. For agents without MCP, every page is also plain Markdown, and a skill teaches them the conventions to keep.

## MCP server

```text
https://uiness.vercel.app/api/mcp
```

Streamable HTTP, no key and no account. It answers from the same registry and pages this site serves, so it is never behind them.

| Tool | What it does |
| --- | --- |
| `search_items` | Finds components, blocks, hooks and docs pages by what they do, best first, each with its install command and docs link. Takes `query`, and optionally `type` and `limit`. |
| `list_items` | Everything in the registry, one line each, grouped by type: `ui`, `block`, `hook`, `lib`, `theme` and `file`. Takes an optional `type`. |
| `get_item` | One item by `name`: description, install command, dependencies, the source of every file with where it lands, and its docs page. |
| `get_docs` | Any page of these docs as Markdown, by `slug`: `installation`, `theming`, `components/button`, `blocks/hero`. |
| `get_setup` | How to set up a project: the registry in `components.json`, the theme, `cn()` and localization, with the snippets from these docs. |

## Markdown and llms.txt

Every page of these docs is also served as Markdown, for agents that read the web and for pasting into a chat:

- [`/llms.txt`](https://uiness.vercel.app/llms.txt) lists every page with a line on what it covers, in the [llms.txt](https://llmstxt.org) format.
- [`/llms-full.txt`](https://uiness.vercel.app/llms-full.txt) is every page in one file.
- Add `.md` to the address of any page: `/docs/components/button.md`. The introduction is `/docs.md`.
- The **Copy page** and **Markdown** buttons at the top of each page do the same from the browser.

In the Markdown, previews become the source of their demos, install blocks become the shadcn command, and links point at the other Markdown pages. The registry itself is JSON with the source inline, at `/r/<name>.json` for each item and `/r/registry.json` for the index.

## Agent skill

A skill tells an agent how uiness is meant to be used before it writes a line: how to install items, where to look up their APIs, and the conventions the registry keeps. Theme tokens instead of colors, `cn()` for classes, the `radix-ui` package, `labels` and `LabelsProvider` for every word, reduced motion, and accessible names, states and keyboard support. Agents that read skills, like Claude Code, load it whenever the work involves uiness.

Install it into the project, at `.claude/skills/uiness/SKILL.md`:

<Install name="uiness-skill" />

Or once for every project, in your home folder:

```bash
mkdir -p ~/.claude/skills/uiness
curl -fsSL https://uiness.vercel.app/skills/uiness/SKILL.md -o ~/.claude/skills/uiness/SKILL.md
```

It is plain Markdown under a short front matter, so agents that do not read skills can take it as a rules or instructions file.
